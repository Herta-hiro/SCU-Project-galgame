# 人设与对话 · 补写手册

这份文档只讲一件事：**你负责的人设和对话，具体写在哪个文件、按什么格式写、写完怎么验证。**

引擎已经改成「人设走数据、对话走剧本」，正常补内容**不用改 C 代码，也不用重新编译**。

---

## 一、先分清三个文件

| 文件 | 管什么 | 改完要不要编译 |
|---|---|---|
| `data/characters.gal` | 人设卡：性格、说话方式、各好感阶段的语气、离线兜底台词 | 不要，直接运行 |
| `data/main.gal` | 剧情对话：旁白、台词、分支选项、AI 支线入口、`@bg` 切背景 | 不要，直接运行 |
| `data/backgrounds/` | 背景图：`@bg 名字` 对应 `名字.png` / `名字.jpg` | 不要，丢文件进去就行 |
| `data/sprites/` | 立绘：`@char 角色id:表情` 对应 `角色id_表情.png` | 不要，丢文件进去就行 |
| `src/*.c` | 引擎：解析、界面、请求 | 要（除非你要改引擎） |

运行方式：双击 `gal.exe`（或 `run.bat`）。依赖的 dll 已经放在同目录。

## 二、人设：`data/characters.gal`

### 2.1 卡片结构

```
:: shenzhiji              ← 角色 id。剧本里用 @shenzhiji:返回节点 引用它
name 沈知霁                ← 显示名，也会写进提示词
persona 21岁，成都某高校历史系大三学生……    ← 人设，写多行会自动换行拼接
rules 1. 严格遵守当前阶段……                ← 行为规则 / 禁忌
scene 成都秋雨天，四川省图书馆三楼靠窗座位。  ← 默认场景
line 玩家坐到对面，把伞收在脚边。            ← 默认“玩家这句话”
player_call 你            ← 她怎么称呼玩家
her_call 你               ← 玩家怎么称呼她
stage0 公事公办，礼貌疏离，不延伸话题。       ← 阶段 0 的语气，0-4 共五档
offline0 沈知霁：椅子没人。                  ← 没配 API key 时的离线台词，按阶段取
# 注释
```

同一个键**写多行 = 自动拼接**（persona、rules、scene、line、stageN、offlineN 用换行连，
name 和称呼用空格连）。所以人设可以像写文档一样一行一点，不用把整段塞进一行。

### 2.2 字数上限（超了会被静默截断）

| 字段 | 字节上限 | 大概几个汉字 |
|---|---:|---:|
| name / player_call / her_call | 40 | 13 字 |
| stage0-4（每档） | 300 | 100 字 |
| offline0-4（每档） | 600 | 200 字 |
| scene / line | 600 | 200 字 |
| persona | 1600 | 530 字 |
| rules | 1600 | 530 字 |

一个汉字 3 字节，标点算 3 字节（全角）或 1 字节（半角）。拿不准就跑校验器，它会直接报哪一行超了。

### 2.3 好感阶段怎么算

好感度 0-100，引擎自动折算阶段，再挑对应的 `stageN` 语气和 `offlineN` 兜底台词：

| 阶段 | 好感 | 关系 |
|---|---:|---|
| 0 | 0-20 | 陌生书友 |
| 1 | 21-45 | 脸熟自习搭子 |
| 2 | 46-70 | 资料互助 |
| 3 | 71-85 | 在意 |
| 4 | 86-100 | 心动 |

所以写人设时**五档语气都要给**，不然某个阶段提示词里是空的。

### 2.4 提示词长什么样

`src/ai.c` 里的模板会把你写的东西拼成下面这样（不用自己拼，知道结构就行）：

```
你扮演游戏女主「沈知霁」。
<persona 全部内容>

当前好感度：30 / 100
当前阶段：1 脸熟自习搭子
当前地点：<@loc>
最近事件：<@event>
已经发生的事：<F5 桌上那滩水；F12 帮拿一半……>
当前场景：<scene，剧本可覆盖>
已知信息：<玩家最近选过的话 + 她最近说过的第一句>
玩家称呼你：你
你称呼玩家：你

行为规则：
<rules 全部内容>

当前阶段语气：<stageN>

输出格式：每行「名字：内容」，旁白写「旁白：内容」，3 到 5 行。
```

`已知信息` 是引擎自动攒的（玩家选的话 + 她回的第一句，滚动保留），你写人设时不用管。

## 三、对话：`data/main.gal`

### 3.1 基本四行

```
:: 节点id                开一个新节点
说话人|台词              一行台词
|台词                    旁白（说话人留空）
-> 选项文字|目标节点      普通分支
```

- 台词里不能出现半角 `|`，需要时用全角 `｜`。
- 一个节点最多 16 行、4 个选项，一行最多 511 字节。
- 节点没有选项时，显示完就「本章结束」。

### 3.2 AI 支线：六列写法

```
-> 选项文字|@角色id:返回节点|玩家这句话|本分支场景|好感度增减|出现条件
```

后四列可省略，省略时用角色卡里的默认值 / 默认规则。例：

```
-> 我就一杯白开水，放我这边|@shenzhiji:after_meet|我就带了杯白开水，放我自己这边。|成都秋雨天，省图三楼满座，她对面刚空出一个位置。|+3
-> 你等到闭馆了？|after_exam|||+2|aff>=46
```

| 列 | 作用 | 省略时 |
|---|---|---|
| 1 | 界面上显示的选项文字 | 必填 |
| 2 | `@角色id:返回节点`，AI 生成完后跳回这里 | 必填（AI 分支） |
| 3 | **玩家真正说出口的那句话**，进提示词 | 用角色卡 `line` |
| 4 | 这一段的场景，进提示词 | 用角色卡 `scene` |
| 5 | 好感度增减，如 `+3` / `-5` | 默认 `+1` |
| 6 | 出现条件：`aff>=46` / `aff<=20` / `aff==0` | 一直显示 |

第六列不满足时该选项**不显示**（剩下的选项自动重新排版），所以同一节点可以写
「好感低时只能客气、好感高了才解锁直球」这种分岔。

**好感度是隐藏数值**：界面上不显示，玩家只通过她的态度感知，写剧情时可以放心用它做分支。
调试想看数字，把 `src/ui.c` 顶部的 `SHOW_AFFINITY` 改成 1 重新编译，右上角就会出现。

普通分支也可以写第三、五列（第三列只用于「已知信息」，第五列照样加减好感）：

```
-> 好，我注意|after_meet|好，我注意。书我不碰。|+2
```

**AI 不跳阶段**：阶段由好感度算出来，低于 46 时她不会主动暧昧。想让剧情升温，就靠选项的好感度增减慢慢堆。

### 3.3 好感度规则（这一章的实现）

- 安静同坐、不打扰：+1~+2
- 守时、还书、带充电宝：+2~+4
- 记住她的研究方向并用上、帮找资料不邀功：+3~+4
- 雨夜送伞但保持距离：+5
- 喧哗、追问排名、过早要微信、低阶段强撩：-2~-6，并触发「礼貌降温」

第一章全对路大概能到 30 左右（阶段 1），阶段 2 以上留给第二章 —— 这是有意的节奏，不是 bug。

### 3.4 背景

节点开头写一行 `@bg` 就能切背景：

```
:: rain_cold
@bg bg_rain_window
|她把包背好，往侧门走。
```

- 图片放 `data/backgrounds/`，名字就是 `@bg` 后面那串（优先 `.png`，其次 `.jpg`）；
- 不写 `@bg` 就沿用上一个节点的背景，所以只在换场景时需要写；
- 图找不到不会报错，会退回深色渐变底（校验器会给警告）；
- 建议尺寸 1920×1080 或任意 16:9，引擎按 cover 方式裁切铺满；
- 现有背景都是 `tools/gen_backgrounds.py` 程序画的，想换实拍照片直接同名覆盖即可，
  细节见 `data/backgrounds/README.md`。

### 3.5 立绘

```
:: meet
@bg bg_lib_window
@char shenzhiji:look
|她抬眼看你一下。
```

- 写法是 `角色id:表情`，文件在 `data/sprites/<角色id>_<表情>.png`；
- 只写 `@char shenzhiji` 用 `normal` 表情；`@char off` 表示这节点不出现人；
- 不写 `@char` 就沿用上一个节点，换表情时才需要写；
- 现在的表情只有四个：`normal` 常态 / `soft` 软下来 / `down` 低头看书 / `look` 抬眼；
- 文件缺失就不画，校验器会给警告；
- 想要手绘或 AI 立绘：透明底、半身、800×1200，命名成同名文件覆盖即可，细节见
  `data/sprites/README.md`。

### 3.6 地点与事件（喂给 AI 的上下文）

```
:: exam_week
@bg bg_lib_window
@char shenzhiji:normal
@loc 省图三楼社科区靠窗
@event C3 闭馆前十分钟
|十一月，考试周。三楼的位置一位难求。
```

- `@loc` 写当前地点，进提示词的「当前地点」；不写就沿用上一个节点；
- `@event` 写最近发生的事件（一行，最多 255 字节），进提示词的「最近事件」；
  一般写成「编号 + 事件名」，比如 `A2 雨伞忘在前台`，模型会去角色卡的事件库里对照；
- `@offline` 写这个节点自己的离线兜底台词（没配 API key 时播放），可以写多行，
  优先于角色卡里的 `offlineN`。**别和节点自己的台词重复**，否则一进支线就像复读；
- 三者都只是上下文，不改变任何判定。

### 3.7 事件库（写在角色卡里）

人设卡里的 `events` 键就是事件库，一行一个事件，写明**触发条件 / 场景 / 行为脚本 /
AI 要点 / 好感结算**，整段会进提示词：

```
events A1 连续同坐第三天｜好感5-15：玩家早到十分钟……结算：安静同坐+1、守时早到+1。
events D4 表白窗口｜好感86-95 且已发生两次 D 类：……给空间+5；纠缠追问-5并降温。
```

写的时候遵守三条：

1. **一行一个事件**，编号（A1/B2/C3…）自己定，模型靠它跟 `@event` 对上；
2. **结算写死数字**（+2 / -5），不要让模型自己掂量；
3. 事件总长上限 7000 字节（约 2300 个汉字），超了会被截断，校验器会报。

AI 回合结束时会输出一行状态栏，格式固定：

```
【好感：55/100｜阶段：2｜记忆：玩家问了索引｜判定：+2，资料相关】
```

这行**引擎解析后隐藏**，玩家看不到（好感度本来就是隐藏数值）。想调试就打开
`src/ui.c` 顶部的 `SHOW_AFFINITY`。

> 注意：好感度的真实数值由剧本第五列决定，模型给的「判定」只用于让它自己保持一致，
> 不会写回存档。想让某个选项真的加 5 点，还是要在剧本里写 `+5`。

### 3.8 自动路由（好感决定进哪个分支）

节点开头写 `=>`，进节点时按好感度自动跳，不需要玩家点选项：

```
:: hub
=> aff>=86 d4_confession
=> aff>=46 c1_index
=> aff>=5  a1_third_day
|（都不满足时才会显示这里的台词）
```

- 从上往下取**第一条命中**的，所以高门槛写在上面；
- 每个节点最多 16 条，条件写法 `aff>=46` / `aff<=20` / `aff==0`；
- 事件节点写 `@once A2` 表示只演一次：演过之后路由会跳过它，停在本档的 hub；
- `@toast 一句话`：进这个节点时右上角冒 1.8 秒提示。安静坐下这类循环点一次没有画面变化，
  用它可以告诉玩家「确实往前走了」，比如 hub 上写 `@toast （图书馆的钟走过一格。）`；
- 目标节点不存在、条件写法错了，校验器会报；
- 完整的好感↔分支对照表在 `docs/好感分支表.md`。

想看某个好感会进哪个分支，不用一路点：

```sh
gal.exe --shot node --node hub --aff 55
# 输出 node=c2_powerbank  aff=55
```

## 四、写完怎么验证

### 4.1 跑校验器（必做）

```sh
python tools/check_script.py
```

它按引擎里的真实上限逐行检查：节点数、行数、字节数、选项数、id 长度、跳转目标是否存在、AI 分支引用的角色是否存在、哪些节点走不到。有错退出码 1。

### 4.2 直接运行看效果

```sh
gal.exe
```

数据文件是运行时读的，改完存盘重开就生效。

### 4.3 定点预览（不用一路点过去）

截图模式，会生成 `shot.png` 然后自动退出：

```sh
gal.exe --shot title                 # 标题
gal.exe --shot game                  # 开局第一句
gal.exe --shot choices               # 选项界面
gal.exe --shot ai --node meet --aff 0   # 从 meet 节点取第一条 AI 分支，好感 0（阶段 0）
```

`--aff` 可以随便改，拿来逐档看她的语气：

```sh
gal.exe --shot ai --node meet --aff 30
gal.exe --shot ai --node meet --aff 55
gal.exe --shot ai --node meet --aff 78
gal.exe --shot ai --node meet --aff 92
```

### 4.4 看她到底会对模型说什么

```sh
gal.exe --prompt --node meet --aff 55
```

不开窗口，直接把这一条分支生成的完整 JSON 写到 `prompt-preview.json`（system 里就是人设、阶段、
已知信息、规则的最终样子）。写人设卡时用它自查：哪一段没进去、阶段语气是不是空的，一眼就看出来。

### 4.5 接大模型看真实生成

没配 key 时走角色卡里的 `offlineN` 兜底台词（流程完整，内容固定）。要真生成：

1. 复制 `data/ai.conf.example` 为 `data/ai.conf`，填 `key=sk-...`
2. 或设环境变量 `DEEPSEEK_API_KEY`（优先级更高）

同一份提示词生成过会缓存到 `data/cache/`，第二次秒出。**改了人设、场景、阶段或玩家台词，缓存键就变了，会自动重新生成**，不会读到旧内容。

## 五、常见坑

1. **半角 `|`**：台词里出现 `|` 会被当成字段分隔符，写成全角 `｜`。
2. **超字节**：一条台词 511 字节封顶，超了尾部直接没了；校验器会报。
3. **AI 分支没写返回节点**：`@shenzhiji` 后面不写 `:节点id` 会停在原地，校验器给警告。
4. **节点走不到**：写了新节点但没人指向它，校验器会给警告。
5. **全角冒号**：AI 返回的台词按「名字：内容」拆行，角色名后面用中文冒号或英文冒号都行，其他符号不行。
6. **改完没反应**：确认改的是 `data/` 下的文件，且是从 `gal` 目录启动（exe 用相对路径读 `data/main.gal`）。
