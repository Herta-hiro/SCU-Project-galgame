## 二、A3 是「打断事件」

A3（索引贴滑落，规则里是 8–16「任意一次同桌」）跨了 A1/A2 的区间，放进自动路由会互相抢，
所以做成**同桌中的打断**：从 `a1_third_day` 的「（点头，继续看书）」进入 `a3_tab`，
在那里面才是真正的分岔——

- 提醒但不伸手 → `a3_ok`，+2
- 直接去碰她的笔记本 → `a3_bad`，−5 并礼貌降温

想让它更容易出现，可以把 `a3_tab` 挂到任何同桌节点的选项上，加一行就行：

```
-> （她翻页时贴纸滑到桌沿）|a3_tab|||0
```

## 四、写法与调整

节点开头的路由块长这样：

```
:: hub
@bg bg_lib_window
@char shenzhiji:normal
@loc 省图三楼社科区靠窗
=> aff>=86 d4_confession
=> aff>=78 d3_cat
=> aff>=75 d2_exam

=> aff>=60 c3_closing
=> aff>=50 c2_powerbank
=> aff>=46 c1_index
=> aff>=30 b3_topic
=> aff>=25 b2_tiandu
=> aff>=21 b1_return
=> aff>=10 a2_umbrella
=> aff>=5  a1_third_day
|（0-4：还没有能触发的事件）
-> 安静坐下|hub|||+1
```

改区间直接改数字；加事件就加一行 `=>`，记得**高门槛写在上面**。
每个节点最多 16 条路由，条件写法 `aff>=46` / `aff<=20` / `aff==0`。

## 四点五、0–20 铺满了（F1–F15）

原来的 0–20 只有 5 个事件，中间大段空白，只能靠「安静坐下 +1」硬点（0→21 大约 15–18 次点击）。
现在补到 15 个一次性小事件，**0→21 约 11 次点击，一次保底都不用点**。

```sh
gal.exe --shot node --node hub --aff N     # 换 N 看会进哪个事件
```

## 五、注意

- 路由是**进节点时**判定的，所以 `hub` 自己不带剧情，只做转发；
- 好感变化后重新进 `hub`（事件结束都回到 `hub`），才会走到下一档事件；
- 事件节点里的选项照样用**第四列**加减好感（`+3` / `-5`），和事件库里的结算保持一致；
  （第五列是场景覆盖，只有 AI 分支会读，普通分支写了会被 `--check` 报错）
- 校验器会检查：路由条数、条件写法、目标节点是否存在、指回自己。`python tools/check_script.py`

## 五点五、负面选择会影响后续好感

「碰笔记 −5」「追问 −3」这类负分选项会正常扣除好感，最低为 0。已经演过的一次性事件仍会跳过，
因此扣分后会按新的好感区间选择尚未触发的事件，不会重复刷已经看过的剧情。

好感始终限制在 **0–100**。负面选择可能让角色关系退回较低阶段；玩家需要通过后续选择重新建立信任。

明确承认具体越界、随后用行动尊重边界，可以获得少量回升；泛泛道歉或替自己辩解不会自动抵消扣分。

## 剧情线索与时间推进

- 第一章开篇埋下坊巷旧名和112页线索；考试周确认不是抄错但缺年份；B3继续找旧目录，C1用索引贴接上新旧名字和改名年份。
- 第二章每触发一个带 `@once` 的事件，按一天推进；游戏在事件开始时显示「又过了一天」。十一月下旬开场，事件经过数周推进到学期末。
- 越界后的修复是具体行为：对书开玩笑后承认不该拿她的书说笑；伸手碰笔记后收手、不找借口、之后不再碰她的东西；邀约被拒后承认问得冒失。

## 五点六、H 段的「距离」（bond）

D4 之后好感基本封顶，H1–H9 的 +2/+3 加不进好感，所以 H 段节点标 `@meter bond`，
数值记进独立的 `bond`：

- 范围 0–100，随存档保存（v7）；
- 不影响 hub 路由（路由只看好感）；
- 调试：`gal.exe --shot node --node h3_sleep --bond 30 --pick 0`，输出里会带 `bond=35`。

## 五点七、结局分档（好感定档，bond 定深浅）

| 好感 | 进入 | 结局 |
|---:|---|---|
| ≥86 | D4 → H1–H9（自动路由，不看选项） | `ch2_end*` 表白线 |
| 46–85 | hub「学期最后一天」（需 `ev>=6`） | `final_friend` 朋友 |
| <46 | hub「学期最后一天」（需 `ev>=6`） | `final_pass` 路过 |

「学期最后一天」以前只要求 `aff<86`，玩家一进第二章就能点它，几十个事件一个不用演。
现在同一行还要求演过至少 6 个事件，两个结局档才真正是「走完一段学期」而不是「立刻退出」。

表白线内部再按 `bond` 分（H9 之后）：

```
:: end_warm_router
=> b>=37 ch2_end_warm          # 搬椅子 + 「……明天也来。」
=> b>=0  ch2_end               # 原版搬椅子

:: end_quiet_router

=> b>=0  ch2_end_quiet         # 原版先走
```

`b`/`bond` 只用于路由，不用于选项显隐（选项条件仍只认 aff）。
D4 里不开口则走 `ch2_end_miss`（第三条结局）。

## 六、每个事件只演一次（@once）

事件节点标了 `@once A2`，进过一次就记进 `seen[EVENT_SLOTS]`（下标 = 事件编号），之后 hub 的路由会跳过它。

**跳过 = continue，不是 break。** 以前命中已演事件会直接停在 hub，结果是「好感 86 且
D4 已演」的存档回到 hub 就什么都演不了、也出不去，只能反复点保底。现在改成跳过已演的、
继续往下找未演的，剩下的按好感从高到低接着来。

本档事件都演完之后停在 hub，只有两个选项：

```
|图书馆的钟走到四点。她翻过一页，把保温杯挪回自己手边。
|（今天没什么特别的事。安静坐着，也算数——总会有下一次。）
-> 安静坐下，看自己的书|hub||2
-> （学期最后一天，收拾东西）|ch2_end_router||0||ev>=6
```

- **「安静坐下」+2**：没有事件可演时的推进手段。以前是 +9，一加就是半个阶段，
  直接把几十个事件跳过去了，所以才「一下就学期末」。
- **「学期最后一天」要 `ev>=6`**：`ev` 是已经触发过的事件数（数 `seen[]` 里的位），
  第六列写 `ev>=6` 就是「至少演过 6 个事件才出现这个收尾出口」。
  以前这行只写 `aff<86`，等于一进第二章就能点它直接跳结局。

`seen[]` 随存档保存（存档版本 **v6**），读档后不会重演已经看过的事件。

调试时想验证“演过之后会跳过”，用 `--seen` 预置：

```sh
gal.exe --shot node --node hub --aff 30 --seen B3
# 输出 node=hub（B3 已演过，停在这里）
```
