### 5.5 AI 支线（2026-11-24 晚重做）

**为什么之前「接了 key 也没区别」**：剧本里只有 **7 个 AI 分支，全在第一章**，
第二章 33 个事件全是写死的普通分支。玩家在第二章怎么玩都碰不到模型。

现在的入口：

| 入口 | 位置 | 说明 |
|---|---|---|
| 7 个原有 AI 分支 | 第一章 meet / day2 / after_index / rain_cold / exam_week / after_exam | 不变 |
| **（自己说一句）** | **所有等待选择的画面** | 引擎自动追加，不在剧本里 |

**「自己说一句」是 ui.c 追加的虚拟选项**，不是剧本节点：

- `visible_count()` 之外多算一块，`ui_choice_rect(k, total)` 的 `total` 比真实选项多 1；
- `ui_choice_hit()` 点中最后一块时返回 `n->choice_count`（越界值），main.c 据此切 `STATE_INPUT`；
- 不占 `Node.choices`，**不受 `MAX_CHOICES=4` 限制**（现有节点最多 3 个选项，加虚拟 = 4，底部 442 < 对话框 455，放得下）；
- 剧本里写 `-> （自己说一句）|@input` 也认，但没必要，`choice_is_ai()` 显式排除了它。

**为什么要做成全局面板而不是只在 hub**：hub 根本停不住——每次回到 hub，自动路由立刻
把玩家带去下一个未演事件，只有全部演完才会显示选项。第一版只加在 hub 里，
玩家几乎永远看不到。

**演完回原位**：`g_free_node` / `g_free_line` 记下开口时的位置，`resume_after_free()`
用 `game_restore_index()`（**不跑路由**）铺回节点，再手动设回 `line_index` 和 `waiting_choice=1`。
不能走 `game_enter_index`：那会重跑路由把玩家带去别的事件，或者把当前事件从头重演。

**不卡死的三道保险**（都别删）：

1. `AiPrompt.no_cache`：自由输入不读也不写缓存。不然同一句话永远得到同一个回答，
   说错一句再想补救，结果原样重复，体感就是「卡在一句话上」。
2. 两层超时：`AI_CURL_TIMEOUT=20`（curl 自身）+ `AI_WAIT_LIMIT=20.0f`（主循环
   `g_ai_wait` 累加）。后者防的是进程卡死、DNS 挂起这种 curl 也不返回的情况。
3. 生成中按 **Esc** 取消：`ai_abandon()` 清流式残留，`resume_after_free()` 回原位，
   **不退游戏、不结算好感**。另外 `ai_request()` 返回 0（上一次还在跑）时走
   `ai_request_failed()` 立即恢复，不会让界面停在等待态。

**自由说话不推进剧情，别把它当成推进手段**：它是一次"插话"，演完 `resume_after_free()`
把玩家放回原位、选项照旧。真正推进会靠 hub 的「安静坐着看书，等下一件事」（+2）：
好感够下一档门槛时，`game_enter_index(hub)` 的自动路由就会带出下一个事件。

两条针对"感觉卡住"的提示（2026-11-24 加）：

- 自由说完按判定弹 toast：`她对这句话有反应` / `她没接这句话` / `她只是听着，没什么变化`。
  以前什么都不说，好感没涨玩家就以为游戏坏了。
- `handle_choice()` 里检测自环：选项 target 是当前节点、走完路由还在原地，
  说明这一档没事件了，提示「还早 · 再坐着看看」或「收拾东西可以走了」。
  不加这个的话玩家会一直点同一个选项，以为死机。

**中文输入**：raylib 不处理 IME，`GetCharPressed()` 收得到 IME 提交的字符但**不显示候选窗**，
盲打不可用。所以补了 Ctrl+V 粘贴（Win32 剪贴板）。注意 `main.c` 里**不能 include <windows.h>**——
它和 raylib 的 `Rectangle` / `CloseWindow` / `ShowCursor` 撞名，得手动声明那 5 个导出函数。

**提速三件套**：

1. `ai_trim_events()`：每条事件带「好感5-15」区间，只传和 `[好感-8, 好感+20]` 有交集的。
   原来 46 条 11KB 全传，现在 7~20 条 2~6KB。**这是首字延迟的大头**。
   注意 `character.c` 解析时已经去掉了行首的 `events ` 前缀，行是 `A1 名称｜好感5-15：…`；
   H 段判断要看编号首字母是 `H`，不能搜「第」——「连续同坐第三天」里也有「第」。
2. `max_tokens: 420` + 输出收窄到 2~4 行 + `temperature: 0.9`。
3. **流式显示，但不遮屏**：`ai_partial_copy()` 每帧把已收到的部分拷出来，
   `feed_ai_stream()` 只留最后 3 个非状态栏行，`ui_set_stream()` 把它们交给 `ui_draw()`
   **直接画进对话框正文**。全屏压暗和「正在生成……」都删了——那一下黑屏太跳，
   背景、立绘、标题现在全程不动，看起来就是她在说话。`start_line()` 里会清掉流式残留。
   调试：`gal.exe --shot stream` 可以截到「生成中」的画面。

`PROMPT_VERSION` 从 2 升到 **3**，模板一改旧缓存全部作废——不然会命中旧缓存，看着像「改了没生效」。

**判定（`【判定：+2】`）**：模型按事件库每条末尾的「结算：……+N」给分，引擎
`parse_judgement()` 取数、`delta_from_judgement()` 换算成 **×3、夹 ±12**。
提示词里加了一段「对不上事件库的时候」基准（帮忙+1 / 搭话 0 / 越界-1 / 重复减到 0），
否则自由发言没有对应事件时判定会飘。控制台每次打一行账：
`[AI] 模型 判定=+2 ×3 → +6   好感 30 → 36`。

**状态栏已瘦身**：从 `【好感：55/100｜阶段：2｜记忆：…｜判定：+2，资料相关】` 改成
`【判定：+2】`——好感/阶段/记忆引擎自己都有，让模型写等于白烧 40 个 token。
`parse_judgement()` 同时兼容旧格式和 `【+2】` 简写。

实测（deepseek-chat，5.9KB 请求 ≈1800 token）：**平均 1.08 秒**（最快 0.68s），
输出 2 行 + 判定。判定有 ±1 抖动（同一输入多次跑出现 +1/+2/0），temperature 已压到 0.85；
要完全稳定得降到 0，台词会变死板。

## 7. 已知问题 / 别踩

- **节点上限 107/160、路由上限 45/72**：加内容还有余量；再改这两个宏要同步 `SAVE_VERSION`
  （`read_bits[]` 按 `MAX_NODES` 序列化，改长度 = 旧档作废）。现在存档是 **v8**
- **第二章节奏是 2026-11-24 重配平的**：回 hub 的选项 9→4 / 6→3 / 3→2，保底「安静坐下」+9→+2。
  改之前从第一章 43 分到表白线只要 3 个事件，玩家体感「一下就学期末」。
  现在 8 个（满分进）～17 个（0 分进）。**别再把这些数值整体调大**，否则又回到 3 个事件
- **「学期最后一天」必须带 `ev>=6`**：以前只写 `aff<86`，一进第二章就能点它跳结局。
  `ev` 是已触发事件数，第六列语法 `ev>=6`，可以和 `aff` 组合（`aff<86 & ev>=6`）
- **`@once` 命中已演事件是 `continue` 不是 `break`**：break 会让「好感 86 且 D4 已演」的
  读档卡在 hub（什么都演不了、也出不去）
- **存档只认 v7**：改存档布局要同步 `SAVE_VERSION` 和 `test_save.c`
- **第一章数值是减半后的**：别再整体 ×3，否则又会一进第二章直接进 D4
- **`@meter bond` 只影响选项数值归属**，不改变路由；路由条件写 `b>=37`
- **AI 失败按剧本值结算**（`main.c` 的 `AI_FAILED` 分支），别删
- **`data/ai.conf` 可能带 UTF-8 BOM**：记事本、PowerShell 的 `Out-File`/`Set-Content`
  都会在开头写 `EF BB BF`，不跳过去的话第一行变成 `\xEF\xBB\xBFkey`，
  `strcmp(k,"key")` 永远不相等，表现是「明明填了 key 却一直走离线」。
  `load_config()` 现在会跳过 BOM（2026-11-24 修）
- **离线开关**：`ai.conf` 的 `offline=1`、命令行 `--offline`、环境变量 `GAL_OFFLINE=1`
  三条路都进 `g_offline`；`ai_is_offline()` 才是「这次要不要发请求」的判据，
  `ai_is_configured()` 只表示「存了 key」
- **改提示词模板必须把 `PROMPT_VERSION` +1**，否则命中旧缓存，看起来像改了没生效
- **`main.c` 不要 include `<windows.h>`**：和 raylib 的 `Rectangle`/`CloseWindow`/`ShowCursor` 撞名。
  剪贴板那几个函数手动 `__declspec(dllimport)` 声明即可
- **`@input` 不是 AI 支线**：`choice_is_ai()` 里显式排除了，加新语法时注意别破坏这个判断
- **立绘白边**：新图先跑 `tools/defringe_sprites.py`，原图在 `_backup/sprites-pre-defringe/`
- **文芷模型是粉丝二创**，模型卡写明“不授予权利”；课程演示可用，公开分发/商用要谨慎
